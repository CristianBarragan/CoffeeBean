# M0.14 — Dependency Graph Freeze

## Purpose

M0.14 is the final M0.x dependency-graph reconciliation before feature work resumes.

The goal is to make the actual project references match the intended Foundgine direction:

```text
                    Foundgine.Abstractions
                     /               \\
                    /                 \\
       Foundgine.Metadata       Foundgine.Semantics
                    \\                 /
                     \\               /
                       Foundgine.Planning
                              |
                              v
                       Foundgine.Execution
                              |
                    Provider implementations
                              |
                         Foundgine.Sql
```

AOT consumes metadata contracts. GraphQL is an adapter above the engine. Providers remain downstream.

## Change

`Foundgine.Semantics` no longer references `Foundgine.Metadata`.

The semantic layer already represented its model using only stable identities and semantic concepts. The previous Metadata project reference and stale `using Foundgine.Metadata;` directives were unnecessary architectural coupling.

The resulting dependency is:

```text
Foundgine.Abstractions
        |
        +---- Foundgine.Metadata
        |
        +---- Foundgine.Semantics
                 |
                 v
          Foundgine.Planning
```

## Rules frozen by M0.14

- Semantics must not depend on SQL, GraphQL, AOT, or physical metadata.
- Planning may depend on semantic contracts and foundational identities.
- Execution consumes planning contracts and semantic result information; it must not depend on SQL.
- SQL may consume execution/planning contracts and physical metadata.
- AOT generates/installs metadata; metadata does not depend on AOT.
- GraphQL is an adapter and may reference the engine layers it adapts, but engine layers must not reference GraphQL.

## Verification

The source dependency graph is checked from project references and source namespace imports. No project-reference cycle is present.

The remaining intentionally downstream references are:

- `Foundgine.Aot -> Foundgine.Metadata`
- `Foundgine.Sql -> Foundgine.Execution + Foundgine.Planning + Foundgine.Metadata`
- `Foundgine.GraphQL.HotChocolate -> Foundgine.Metadata + Foundgine.Semantics + Foundgine.Planning`

These are adapter/provider relationships rather than upward dependencies.
