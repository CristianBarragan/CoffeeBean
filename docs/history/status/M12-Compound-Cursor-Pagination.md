# M12 — Compound Cursor Pagination

M12 extends forward keyset pagination from primary-key-only cursors to arbitrary root ordering with a deterministic primary-key tie breaker.

## Semantic contract

A request may specify:

- one or more semantic order terms
- `first`
- `after`

The semantic layer carries field identities, directions, and an opaque cursor. It does not contain SQL seek predicates.

## Effective ordering

If the requested order is:

```text
Name DESC
```

and `Id` is the primary key, the provider uses:

```text
Name DESC
Id ASC
```

The primary key is appended only when it is not already present.

## Cursor

The cursor contains the values of the complete effective ordering tuple.

Example:

```text
["Bob", 2]
```

The encoded cursor is opaque to the semantic layer.

## SQL

For:

```text
Name DESC, Id ASC
```

and cursor:

```text
["Bob", 2]
```

the provider generates the lexicographic seek:

```sql
WHERE
    Name < @p0
    OR (
        Name = @p0
        AND Id > @p1
    )
ORDER BY
    Name DESC,
    Id ASC
```

The predicate is generated by the SQL provider and values are parameterized.

## Boundary

```text
Semantic
  field + direction + opaque cursor
       ↓
Planning
  provider-independent execution
       ↓
SQL
  lexicographic seek + ORDER BY
```

The archive's ordering and pagination implementations were used as algorithmic evidence; their old query/SQL architecture was not migrated.
