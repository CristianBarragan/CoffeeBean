# Foundgine.Samples.Banking

Answers "why is Foundgine not just Graphgine?" with a repository sample
instead of a slide.

```
Domain
   ↓
Foundgine.Metadata      (hand-written — see Metadata/BankingMetadata.cs)
   ↓
Foundgine.Builders      (logical QueryPlan)
   ↓
Foundgine.Execution.Contracts   (physical ProviderPlan)
   ↓
Foundgine.Providers     (SQL provider — not implemented yet, throws
                          NotSupportedException with an explanation)
```

No GraphQL. No HotChocolate. No `Graphgine.*` project anywhere in
`Foundgine.Samples.Banking.csproj`'s dependency graph — that's the entire
point. Run it with:

```
dotnet run --project samples/Foundgine.Samples.Banking
```

It walks through the same tiny two-table domain
(`Customer`/`Account`) that `samples/Graphgine.Samples.Banking` uses, but gets
there as a plain console app talking to the platform directly, and stops at
the one honestly-unimplemented boundary in the whole pipeline: the SQL
provider. Everything before that point — metadata, logical plan, physical
plan — is real.

## Compare with `Graphgine.Samples.Banking`

|  | This sample | `Graphgine.Samples.Banking` |
|---|---|---|
| Fronted by | Nothing — a console app | GraphQL via HotChocolate |
| Metadata | Hand-written | Generated by `Graphgine.SourceGenerators` from mapping classes |
| Depends on | `Foundgine.*` only | `Graphgine`, `Graphgine.HotChocolate`, `Graphgine.SourceGenerators` |
| Purpose | Show the platform on its own | Show the platform's first product |

If someone can't tell the difference between "Foundgine" and "Graphgine" from
the docs alone, point them at these two folders side by side.
