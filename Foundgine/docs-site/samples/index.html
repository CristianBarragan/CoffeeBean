Reference applications

Samples

The samples are a progression: first understand the layered application, then exercise the semantic boundary, then attack the transport/security boundary.

The learning path

SamplePurpose
Foundgine.SupplyChainCanonical layered application: API, Application, Domain, AOT, Semantics, infrastructure, MCP, PostgreSQL and tests.
Foundgine.SupplyChain.SimpleSingle-project variant showing that the architecture is based on boundaries, not assembly count.
Foundgine.SupplyChain.SemanticAdvanced semantic showcase: recursive relationships, bounded traversal, authorization-aware planning, temporal reasoning, aggregation, mutation dependency graphs and provider-backed retrieval.
Foundgine.SupplyChain.PenTestSecurity-regression harness that treats MCP and GraphQL as untrusted transport boundaries.

Why separate samples?

The canonical sample teaches composition. The semantic sample deliberately increases semantic difficulty. The PenTest sample focuses on adversarial behavior. Keeping those purposes distinct makes each one easier to understand and maintain.

Benchmark relationship

The benchmark workload is kept separate from the evolving reference sample. Benchmark fixtures are controlled experiments; samples are architectural teaching material.
