Choosing where to start

  • Application developer: start with Foundgine and Foundgine.Sql.
  • Semantic/application architecture: read Foundgine.Semantics, Foundgine.Metadata and Foundgine.Planning.
  • AI integration: read Foundgine.AI and Foundgine.MCP.
  • GraphQL integration: use the Hot Chocolate adapter family and keep host-owned execution context outside the transport.
  • AOT: use Foundgine.Aot with Foundgine.Aot.Generator.
  • High assurance: understand Foundgine.Execution and the optional Foundgine.Security.Authority boundary.

Boundary rule

If a type needs PostgreSQL, SQL syntax, GraphQL, MCP, Microsoft.Extensions.AI or another provider/transport implementation, it should live outside the provider-independent abstraction and semantic contracts.
