Get started with Foundgine

Run the canonical Foundgine.SupplyChain sample and follow one request through API, application, domain, AOT metadata, semantics, planning, SQL and MCP.

What you will run

Agent / MCP client
      ↓

      ↓
Application capability
      ↓

      ↓
Foundgine semantics
      ↓
Planning / ExecutionIR
      ↓
Foundgine.Sql
      ↓
PostgreSQL

Prerequisites

  • .NET 9 SDK
  • Docker with Compose support
  • A clone of the Foundgine repository

Start PostgreSQL

docker compose -f docker-compose.postgres.yml up -d

Use the repository's supplied connection/configuration for the sample rather than creating a second persistence abstraction.

Run the API

dotnet run --project samples/Foundgine.SupplyChain/Api

The exact local commands and environment settings are maintained in the sample's GUIDE.md. The website intentionally explains the architecture rather than duplicating every shell command.

Walk the layers

1 — API

Maps transport requests into application calls. It should not know how SQL is written.

2 — Application

Defines business capabilities and orchestrates domain operations. This is where application authority and use-case boundaries remain explicit.

3 — Domain

Contains domain records and business concepts. Foundgine metadata declarations describe their structural shape.

4 — AOT metadata

Foundgine.Aot.Generator discovers declarations at compile time and emits generated metadata. This supports deterministic startup and Native AOT-friendly execution.

5 — Semantic model

The sample maps structural metadata into application semantics: entities, fields, relationships, capabilities and authorization rules.

6 — Queries

A query repository builds semantic operations rather than SQL strings. The planner turns those operations into provider-independent execution.

7 — Mutations

Ordinary mutations use semantic mutation planning. High-assurance operations retain explicit PostgreSQL SQL where domain invariants depend on transactional database features.

8 — MCP

MCP is a protocol adapter. It does not become the source of authorization.

9 — Testing

Tests cover semantic contracts, generated metadata, planning, provider compilation, PostgreSQL integration, MCP contracts and end-to-end behavior.
