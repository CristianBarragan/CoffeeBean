End-to-end evidence · Run 4 · 17 August 2026

Compare execution architectures: semantic MCP + Foundgine versus a conventional GraphQL + EF Core agent path

Run 4 changes the question. Instead of only asking how much work the agent performs, it compares two complete execution paths across a 4 × 4 matrix: 10, 100, 1,000 and 10,000 customers at concurrency 8, 16, 32 and 64. Each cell uses five warmups and 30 measured runs.

Inspect the matrix evidence →All five runs
Why this run existsThis is the main performance experiment. It tests whether Foundgine's semantic execution boundary can reduce agent-side work while also improving the database/application execution path for a relationship-heavy graph workload.
What was comparedGraphQL + Hot Chocolate + EF Core versus MCP + Foundgine across workload/concurrency cells.
What it meansRun 4 provides the strongest evidence for Foundgine's graph-query execution model. The result is not evidence that every workload will be faster; it is evidence that this deterministic relationship-heavy graph workload benefits substantially from the execution architecture being tested.
Published finding
What the evidence says

Across the published 16-cell matrix, Foundgine used 1 tool call per flow versus 3.5 on average for the conventional path, and estimated context load averaged about 205.6 versus 1,617.2 tokens (87.3% lower). Foundgine recorded higher RPS in every published cell, with the advantage ranging from roughly 3.8× to 33×. Average wall time was about 5.2 ms versus 44.8 ms across the published samples. All published samples recorded zero failures.
