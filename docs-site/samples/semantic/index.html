Supply Chain Semantic

A deliberately difficult example of semantic execution: the model is richer than CRUD and the caller is treated as untrusted.

What it demonstrates

  • Recursive and multi-hop relationship traversal.
  • Bounded traversal and semantic relationship paths.
  • Entity, field and relationship authorization.
  • Tenant-aware conditional predicates.
  • Temporal and aggregate constraints.
  • Semantic mutation graphs and generated-value dependencies.
  • Manual semantics alongside metadata-derived structure.
  • Provider-backed approximate retrieval with explicit strategy boundaries.
  • Fail-closed client-supplied claims that can narrow access but never widen it.

Provider-backed retrieval

The semantic layer defines the retrieval contract; PostgreSQL supplies optional physical strategies. Current PostgreSQL strategies include fuzzy matching through pg_trgm, native full text, optional pg_search/BM25 and optional Apache AGE graph similarity. Vector retrieval is intentionally reserved for a future provider.

Client claims

The sample demonstrates that caller-supplied claims are untrusted input. Reserved identity keys fail closed; recognized claims are validated individually; unknown claims are dropped. Accepted claims can only add restrictions such as read-only scope or warehouse predicates.
