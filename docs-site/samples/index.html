Reference applications

Foundgine samples

Three reference applications form a deliberate progression: learn the layered architecture, stress semantic execution, then verify the security boundary across multiple transports.

A progression from architecture to security

Sample Purpose
Foundgine.SupplyChain The canonical layered sample covering API, Application, Domain, AOT, Semantics, Infrastructure, MCP, PostgreSQL, and tests.
Foundgine.SupplyChain.Semantic An intentionally difficult semantic showcase covering recursive relationships, bounded traversal, authorization-aware planning, temporal reasoning, aggregation, mutation dependency graphs, and adversarial domain data.
Foundgine.SupplyChain.PenTest A security-regression harness exercising MCP and GraphQL against the same hardened application and PostgreSQL boundary.

The learning path

1. Learn the physical architecture

Start with Supply Chain to see how API, application, domain, semantic, planning, infrastructure, and persistence layers fit together in a working .NET application.

2. Understand the semantic boundary

Continue with the Complex Semantic Showcase. It deliberately avoids a simple CRUD demonstration and instead exercises recursive graph traversal, authorization-aware planning, temporal constraints, aggregation, mutation dependency planning, and hostile data.

3. Verify the security boundary

Finish with the Security PenTest sample. MCP and GraphQL are treated as untrusted transport adapters while authentication and authorization remain centralized in the application layer.

Why the samples are separate

Each sample answers a different architectural question. Supply Chain asks “How are the layers assembled?” Semantic asks “What can a semantic execution boundary safely express and plan?” PenTest asks “Does the same security boundary remain intact when requests arrive through different transports?”

Together they demonstrate the intended Foundgine flow: caller intent → semantic model → resolution → authorization → planning → execution → persistence.
