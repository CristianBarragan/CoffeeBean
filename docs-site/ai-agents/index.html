AI agents · host-owned authority

AI agents with Foundgine

Give an agent useful application capabilities without giving the model database authority. Foundgine keeps semantics, authorization and physical execution under application control.

The anti-pattern

LLM
 ↓
generated SQL
 ↓
database credentials
 ↓
PostgreSQL

This collapses intent, authority and execution into one untrusted generation step.

The tool-surface version of the same problem

Replacing raw SQL generation with a set of individual tools doesn't remove the risk if each tool is free to implement its own authorization, tenant filtering and query logic on the way to the database.

Agent
 ├─ Tool A → its own auth / filtering / query logic
 ├─ Tool B → its own auth / filtering / query logic
 └─ Tool C → its own auth / filtering / query logic

An agent with dozens of tools can end up with dozens of independent execution and security surfaces, each only as correct as the person who wrote that one tool. Routing every tool through the same semantic and authorization boundary answers "what does this mean, and is this caller allowed to do it" once, consistently, regardless of which tool the model called.

The Foundgine pattern

LLM / agent
   ↓
capability discovery / structured intent
   ↓
Foundgine
 ├─ resolve
 ├─ validate
 ├─ authorize
 ├─ plan
 └─ execute
   ↓
provider

Capability discovery is advisory

foundgine_capabilities can describe the semantic surface available to the current context. That description is guidance for constructing intent, not a credential. The actual request is resolved and authorized again.

What Foundgine.AI provides

The package integrates Foundgine with Microsoft.Extensions.AI. It exposes a controlled tool surface and a bounded function-calling loop. It does not hard-code an OpenAI, Azure, Ollama or other model provider.

Security scenarios to test

Allowed fieldAgent requests a field that the semantic contract and current authorization permit.
Forbidden fieldAuthorization rejects the field before provider execution.
Cross-tenant accessTenant predicates are application-controlled and cannot be replaced by caller claims.
Prompt injectionUntrusted data is data; it does not gain authority to rewrite the semantic or security boundary.

What Foundgine does not claim

Foundgine is not a general autonomous-agent framework. Model selection, memory, orchestration, deployment and autonomous behavior remain the responsibility of the surrounding AI application.

The same restraint applies when an agent's input is free-form language: Foundgine will tell an agent when its own words were ambiguous against the semantic contract (see Grounding decisions) rather than letting the model's confidence stand in for a correct interpretation. See What Foundgine is designed for for how the agent-tool category relates to the others.

Agents use the same pipeline

An AI agent is simply another untrusted caller. Model output, capability discovery and retrieved candidates all enter the same semantic operation graph, resolution, authorization, plan binding and execution boundary — see the full canonical architecture diagram on the Architecture page.
